# 营销测试隔离故障补验

日期：2026-10-18。新增真实模型/付费调用 **0**，Meta 写入及广告发布 **0**。故障只注入本机隔离环境；没有改动生产工作区、凭据、费用上限或报表。

## 结果

补齐导出提交中断、重复任务、损坏文件、报表丢响应及竞争更正的检查，发现并修正两处问题：

1. 本地 BlobStore 的生成文件提交原来直接覆盖目标文件。ZIP 已落盘但响应丢失，或进程在落盘后中断时，重试会改变文件版本；不同内容的同名提交也会覆盖原文件。现在按目标加锁，相同内容保留原版本，不同内容拒绝，先复制到同目录临时文件再原子发布。普通复制异常清理临时文件，不暴露半成品。本次修复属于本地存储适配器；不将其冒充生产 S3 兼容存储的故障验收。
2. 营销工作流后台刷新失败时，页面原来直接卸载测试区，已选 CSV 和勾选随之丢失。现在保留已有页面及输入，显示刷新提示，暂停业务动作并隐藏缓存下载链接；刷新恢复后继续操作。没有已加载数据的首次失败仍显示重试入口，不展示虚构状态。

本次隔离验收完成时修复尚未部署；随后同日已按用户要求上线，Safari 剩余恢复/下载/重载步骤也补验通过，详见 [上线复验](marketing-fault-release-verification.md)。本文保留隔离验收当时的范围，没有从空工作区重跑整个真实模型闭环；历史完整闭环证据仍保留原有日期和范围。

## 故障矩阵

| 场景 | 检查结果与层次 |
| --- | --- |
| ZIP 提交已完成、存储确认响应丢失 | 本地真实文件 + 领域 HTTP；失败后明确重试，冻结清单不变，复用同一个文件版本；新 Operation 只完成一次 |
| ZIP 提交后进程中断 | 领域 Worker 在提交后用受控 `BaseException` 中断；恢复同一个 Operation 和文件版本。这里不是生产 Worker 的真实断电测试 |
| 已完成导出任务再次投递 | 不重新读素材或写 ZIP，不追加第二次成功事件 |
| 素材流截断、等长字节损坏 | 整包失败，校验前不提交 ZIP；截断场景恢复后可明确重试 |
| 两个导出执行重叠，其中一个延迟失败 | 协程屏障控制实际交错；已完成导出不被后到失败改成失败 |
| 本地文件复制中断、同名内容冲突、四个同时提交 | 中断不发布半成品；冲突保留原内容；相同内容并发返回同一版本 |
| CSV 确认成功但客户端未收到响应 | 相同请求身份重放，不生成重复有效批次或重复统计；模拟花费仍为 455 |
| 两份更正预检均通过，先后确认竞争 | 第一份生效，第二份确认时重验拒绝；不修改失败命令的轮次版本；有效模拟花费为 456 |
| 无效数值及损坏行 | NaN、负数、Infinity、公式、非整数展示量、超限金额、过高精度、缺列行，共 8 个子场景；整批不可确认，无有效行混入统计，也不认定业务达标 |
| PostgreSQL 事务中断 | 独立受控 Mock 租户，最小权限 `marketai_domain_api`；真实子进程在修改/flush 后、提交前强制退出，版本和数据完整回滚，随后可正常确认 |
| PostgreSQL 并发更正 | 两条真实数据库连接配合屏障；一个确认成功，另一个返回旧版本冲突；携带新版本再试仍拒绝过时替代，只保留一个有效批次 |
| 浏览器后台刷新断连与恢复 | 修复版内置浏览器：选 CSV 并勾选后停止本机 API，表单保留、业务按钮暂停；恢复 API 并刷新后，用原文件继续预检，显示数值及重复行问题，不出现确认入口 |

最后一项使用既有已结束 Mock 小轮，另追加一份带问题的预检，没有确认导入。前后只读核对：35 行、一个有效批次、模拟花费 491、原关闭记录、评估、导出清单与文件引用，以及策划/生成/QC/修订数量均保持不变。它不代表真实 Meta 支出。

## Safari 的另一条路径

通过 Finder 定位并打开 Safari.app，确认运行后再绑定窗口，绕过上次直接启动时的长时间超时。实际 Safari 18.6 已通过：隔离账户登录、当前审核页及模拟提示、已结束小轮历史/结果、原生 CSV 文件选择。

隔离网页原先在 `127.0.0.1` 与 `localhost` 之间切换，Safari 登录发生循环。仅将本轮本机网页的规范地址和认证地址统一为 `http://localhost:4283` 后登录成功；没有关闭浏览器安全保护或改变生产认证配置。

原生控制随后多次被打断，因此当时修复版 Safari 的后台刷新断连恢复、预检后重载和私有 ZIP 下载未验完；这些步骤已在后续 [上线复验](marketing-fault-release-verification.md) 用实际 Safari 补齐。没有把内置浏览器结果算作 Safari 通过，也没有将桌面 Safari 的局部验收扩大为 iOS、触屏或全部 WebKit 兼容验收。
