## 2. 建议领域边界与关系

以下是领域职责与关系概览。契约和迁移已有实现，正式字段与路由以 `app/marketing/` 及生成的 OpenAPI 为准，本表不替代 API 合同。

| 领域对象 | 负责的真值 | 关键关系与版本边界 |
| --- | --- | --- |
| 产品理解版本 | 品类需求、本产品理由、客群/情境/顾虑、事实与推测 | 引用 ProductVersion 和来源；编辑/确认生成可追溯版本 |
| 广告角度、表达建议、创意组合版本 | 主张、讲法、适配理由、元素与依据 | 表达关系允许复用与新增；组合固定一个角度+表达+元素配置 |
| 大轮 | 业务目标、适用条件、总预算、路线与终止结果 | 包含小轮；预算区分媒体/供应商，不以 UI 进度作为状态 |
| 小轮与方案版本 | 一个问题、设计、判断与停止规则 | 确认版本关联测试组；投放前另冻结素材与条件清单 |
| 测试组与素材成员 | 本轮比较对象与组内执行 | 多对多业务引用；素材属于哪个组由显式关系决定，不能按标签推断 |
| 测试意图/执行快照 | 方案到 Prompt、文案、QC 的一致性 | 生成 RunItem 引用组合和测试意图；保留实际 Provider/模型/成本 |
| 投放清单、广告绑定、回传批次 | 导出身份、实际广告对应、原始指标来源 | 账户+ad_id+适用期间明确引用清单；原始文件不可覆盖，修正可追溯 |
| 评估快照与结论 | 业务达标、相对比较、认识范围和局限 | 精确引用设计、实际配置、规则和指标版本；计算可重放，AI 解释可追源 |

不能只把新术语塞进 `marketing_vars_json` 或素材 tags：测试组成员、冻结边界、投放映射和证据引用应具有可校验关系。是否复用旧 Experiment 聚合及哪些数据迁移，由 S0 用真实旧数据样例验证后决定，禁止先强制一对一映射。

状态要分开：产品理解/方案确认、生成任务、质量审核、外部投放记录、数据质量/成熟度、小轮评估、大轮结束。测试页的“当前步骤”是这些状态的服务端投影，不能用一个可手改的前端 step 代替。

## 3. 实施切片与完成门槛

### S0：冻结新契约与旧数据兼容方式

依赖：本规格。产出：可直接开发的领域 schema、API/事件、状态转换和迁移设计。

- 定义上述对象的归属、稳定身份、版本、引用、状态与错误码；区分方案确认、生成冻结、投放冻结。
- 用“不同表达数量”“组内多素材”“单方案达标复测”“旧实验未知问题”四种样例走通关系；决定旧 Experiment 的兼容边界，不修改旧语义。
- 定义文件回传来源/核验状态与现有 Meta 证据模式的关系，禁止用一个 mode 字段混淆数据来源与测试环境。
- 明确本地化/放量如何识别可用的达标证据；尚未定义的输入保留原门禁，不自动转换 Winner。
- 为每个新付费 LLM/视觉调用定义 BYOK 绑定、报价、预留、上限和 uncertain 行为，不能复用旧全局 Key 回退。
- 按现有版本化 OpenAPI/BFF 机制规划合同演进；不由前端自建未登记 API。

完成门：方案字段可完整表达所有关键验收场景，旧记录保留原快照/算法/来源且不会自动变成已验证角度；迁移与 API 兼容有具体样例。需要方法选择的统计任务在此列清输入输出，S5 才实现正式评估。

### S1：产品输入 → AI 理解 → 用户确认

依赖：S0。产出：用户能从产品信息获得可修改、可恢复的结构化理解。

- 接现有产品导入/已发布产品，最小支持粘贴文本，保留原始输入与来源。
- AI 分开整理品类需求与选择理由，再补客群、情境、顾虑；事实、推测独立持久化。
- 缺失与冲突可见，用户改写/确认有 revision，不把认可推测写成投放结论。
- 页面无需产品 ID；刷新恢复草稿和确认状态；AI 不可用时可保留输入和重试，不暗中展示通用模板为产品分析。

完成门：认证信息缺失不捏造事实；确认与编辑不会改写历史；跨 Workspace 引用拒绝。付费调用遵守 S0 边界。

### S2：AI 建议角度/表达 → 确认小轮方案

依赖：S1。产出：完成首次三步流程，得到可执行、可解释、尚未付费生图的测试方案。

- 动态生成角度及各自表达、适配理由与证据缺口，默认按角度分组；支持直接改、新表达和不同数量。
- AI 选择候选与测试组安排，起草问题、比较方式、控制条件、业务目标、预算分配和停止规则。
- 规则校验关键字段、预算可行性和设计与预期结论是否相符；缺少业务目标不能确认正式测试。
- 确认后创建大轮及第一小轮的方案版本，进入统一测试页；生成设置作为后续执行项，不让用户手动拼变量。

完成门：三表达对两独有表达完整保留；多因素变化的计划不承诺单因素结论；预算不足时有明确缩减建议。无基准仍能按业务目标确认；单方案复测显示不做相对比较。此切片完成不能宣称投放闭环已完成。

### S3：方案驱动生成、营销 QC 与质量审核

依赖：S2。产出：同页得到符合测试意图的已审核素材。

- 将确认组合和意图映射为现有 GenerationDraft/预览/RunItem，复用 Gemini、OpenAI、Seedream 与受控 Mock；保持现有成本、防重及恢复能力。
- 冻结 Prompt、配套文案、产品依据、主张、对照要求、Provider/模型和版本；变更后重新预览确认费用。
- 补产品/事实、主张、表达及成对对照检查；视觉服务和人工检查均保留明确来源，不能由文件检查冒充完成。
- 准确 AssetVersion 审核、部分成功、相关反馈再生成与新版本重新审核接入测试页。

完成门：产品外观正确但未突出指定主张/对照的图片被识别并阻塞；任务成功或 Approved 不产生有效性结论。刷新/丢响应不重复付费，未完成或 uncertain 不显示成成功。

### S4：导出 → Meta 人工投放 → 可追溯数据回传

依赖：S3。产出：用户能把本轮素材交给 Meta，再将数据准确对应回同页。

- 审核后冻结投放清单，生成可读名称、稳定映射键、文案、ZIP/Manifest 与投放指引。
- 接广告账户/ad_id 绑定与实际配置确认，支持同素材不同广告/期间；导出状态与真实 delivery 分开。
- 首先实现文件上传、字段映射、预检、用户确认导入、原始归档与版本；优先支持含日期、ad_id 和目标所需原始指标的 Meta 报表。缺列时显示可修复错误，不手填模拟绩效。
- 校验币种、时区、归因、重复/修正、累计/按日粒度；隔离未匹配行，不能把缺失补零。
- 只读同步按既有授权和模式独立接入，不为完成此切片增加客户 Meta 写操作。

完成门：改名不丢关联；重复上传不重复计数；修正版可审计；跨 Workspace/模式不可混入。真实客户文件支持状态、来源与核验能力必须在 UI 明示。此切片仅说明数据已接通，尚不能用旧 verdict 伪装新结论。

### S5：有边界的评估、解释与大轮结束

依赖：S4。产出：完整交付“哪些值得投、证据是什么、下一步是什么”。

- 评估器读取方案、实际投放、数据质量和指标快照，分别输出业务达标、相对比较、认识范围；先决定可比性/充分性，再计算结果。
- 用样例选择并版本化相对比较、组内多素材汇总、分配偏差处理、区间与多次评估方法；复用旧计算工具需证明适用范围，禁止直接给旧 win 改名。
- AI 根据确定性结果解释证据与局限，引用具体素材/组合/指标，不自改数字或提升因果等级；解释失败时仍可显示基础评估。
- 显示预算余量、截止日、下一步价值与成本；继续动作先创建待确认方案。到期、预算耗尽与证据不足都能正常收尾。
- 生成为用户可读的结束交付，并区分单条有效素材与可复用组合；改规则重评保存新版本，不覆盖原判断。

完成门：两组同时达标、相对最好但未达标、数据不足、组内素材/分配不等、混杂组合、单张成功、新版本未重复成功及预算耗尽均有正确结果。相同冻结输入可重放同样的基础判定。达到此门槛后才可称首条营销测试闭环完成。

### S6：首条闭环硬化与切换验收

依赖：S5；各前序切片已经完成自身必要验证。产出：可恢复、可审计的登录后闭环证据。

- 从空 Workspace 在 PostgreSQL 经真实登录/BFF/领域服务走通三步开始与同页全流程；仅外部 AI/Meta 可替换为标记明确的受控 adapter。
- 验证用户撤销、跨租户/RLS、Worker 重启、导入中断、费用不确定、部分结果、刷新恢复和历史兼容；关键动作的可访问性及手机布局同步验收。
- 用规格中的 12 个场景验收；发布说明分别列出受控路径、真实文件回传和真实供应商/Meta 的实测范围。
- 先验证后切换主入口；旧数据保留只读访问和原有解释，不覆盖历史决策，也不通过重写旧前端制造第二套业务真值。

完成门：可用代码、自动化证据与人工走查共同证明；不能把预置演示、SQLite 单测或 PAUSED canary 视为真实业务有效性。

### S7：扩展表达匹配、组合复测与后续复用

依赖：S6。产出：在同一组织模型上完整覆盖大轮的后续路线。

- 首条闭环已支持有边界的下一轮建议与大轮结束；本切片进一步优化匹配表达、搭配关系专测、可选元素优化与新增执行复测的推荐和比较视图。
- 用历史证据推荐数量、预算和顺序，保留新表达与探索空间，不制造永久 Loser 黑名单。
- 独立落实本地化与放量的新证据消费门禁；未通过者保留旧隔离边界。跨客群/产品学习按适用性审核，不自动汇总标签。

完成门：新增版本与新增投放支持才提升组合复用性；推荐不会越过剩余预算或用户确认。首条闭环不依赖本地化、放量或视频制作能力完成。
