# 营销测试：审核、Meta 交接、回传与评估

状态：首条闭环已上线，默认入口为 `/w/{slug}/experiments`；2026-10-16 本机受控闭环为历史验收，后续真实模型与生产复验见 [上线记录](ai-marketing-production-release.md)。沿用 Workspace 登录、BFF、幂等请求、费用确认和现有生成服务。旧 Experiment/Launch/Scale 数据不迁移为新结论。

## 同页流程与冻结边界

确认产品理解和方案后生成各组合素材。投放前确认开始日期、周期、Meta 账户时区、真实/模拟模式及判断协议，创建不可变小轮快照。真实模式不能补登记过去的开始日期；时区使用 IANA 名称。周期须与方案一致。新小轮需先结束旧轮、修改并重新确认方案；大轮预算和次数上限按首次冻结方案执行，编辑计划不能悄悄重置。

系统只接受服务端可信生成配方中的项目、方案修订、组合和模式关系。营销 QC 现由 AI 先读取精确图片、配套文案、已确认事实和对照要求，自动填检查结果、依据和修正建议，再由用户集中确认或单项调整。通过项默认收起，不再要求用户逐图从头填写整套表。缺真实产品参考图时保留外观身份的待确认项，可集中核对；无法判断或清楚失败的项目不会默认通过。文件 QC 阻断继续有效，具体因素的审核与导出保留实际对照版本。费用、报告校验和人工调整规则见 [AI 营销 QC](ai-marketing-ai-qc.md)。

审核通过不产生效果证据。导出冻结每个具体版本及其文案，覆盖每个计划组合，不能把不同表达悄悄删掉后按原方案解释结果。冻结后需要修改素材时结束本轮、重新确认新方案。其他入口撤回质量审核后，新下载链接被阻止，打包完成前再次重验资格；原包保留历史。撤回后恢复通过也不恢复旧评估，需追加新评估与新交接。

后台 `marketing.export` 读取精确存储版本并核验内容哈希，生成真实私有 ZIP；同内容文件去重但保留各广告用途。包内包含图片、`ads.csv`、`manifest.json`、每日回传空模板及使用说明。广告名含稳定短键，正式对应以冻结条目和实际 Ad ID 为准，不依赖广告名称。包中自由文本 CSV 单元格做公式防护。当前支持 PNG/JPEG/WebP 图片，每个文件最多 20MB，最多 60 个版本、总计 100MB。

ZIP 写入固定对象键，重复执行不覆盖不同内容；本地及 S3 的同内容写入可恢复。失败可显式重试同一冻结选择，不产生图片服务调用。下载沿用审计 DownloadIntent 和短期签名 URL，图片和 ZIP 不经过 FastAPI/Next 中转。API、Worker 需配置相同私有 BlobStore；S3 必须启用版本控制。

## Meta 人工投放与 CSV

用户在 Meta Ads Manager 创建广告，再在同页绑定账户、Ad ID 和冻结条目，确认实际客群、优惠、落地页、版位和比较条件；不同实际配置明确记录偏差。一条素材可对应多个真实广告。相同账户/Ad ID 在重叠日期只能对应一条记录；同一小轮使用同一账户。导出和绑定不是已验证的 delivery。

使用 USD、已冻结账户时区、7 天点击 / 1 天浏览归因，导出**每个广告每天一行，无 breakdown**。最多 256KB UTF-8 CSV、5,000 行。默认模板列：

```csv
date,ad_id,spend,impressions,clicks,purchases,purchase_value
2026-10-16,123456789,25.50,1200,30,2,119.80
```

支持常见英文 Meta 表头及显式列名对应。`clicks` 是 Link clicks。CPA 需 purchases，ROAS 还需 purchase_value；CTR 仅用于探索。数值必须有限、非负、无货币符号及千分位，日期为 YYYY-MM-DD；订单可保留归因小数。缺失是未知，不补零。没有投放的广告日需要报表中的明确零行；缺日会限制评估。

上传文本先预检，列出无法对应、重复、越界和缺失数据；有问题整批不能确认，不静默丢行。确认前显示原始文件名、行数、来源及问题，并明确核对报告上下文。确认后原文、哈希、上下文、字段映射和标准化行保留。

同一请求/文件上下文重复提交复用批次；不同文件包含已入库广告日也不能再次计数。修正版必须明确替代当前有效批次，保持同一广告日集合及报表上下文。旧批次保留，新评估只读更正链末端。确认和并发更正再次验证冲突。

真实模式接受 `customer_file`，模拟模式仅接受 `controlled_mock`。来源始终为**用户提供，未独立核验 Meta 来源**，不能自动转换为 Meta API 独立证据或旧实验相对 Winner。新增显式交接需要最新成熟的真实回传、精确素材业务达标和当前审核资格，并确认适用的已发布产品/销售方案；之后可准备本地化。放量发现还需新增执行与另一轮支持的组合，继续满足市场真值、权利和实际投放对象匹配。更正或撤回会使旧交接失效；准备与建议均不创建或发布 Meta 广告。

## 判断规则与结论边界

判断协议在投放前冻结，默认最低 7 个完整日、每个判断对象 1,000 展示、20 点击、20 购买（CPA/ROAS）和 20 USD 花费。默认结束投放后再等待 8 天，并只在最终检查点判断；未成熟可以查看不足原因但不能提前称为达标。参数可在冻结前调整，有服务端最低边界。

同时评估计划测试组和每条精确广告：先把广告日原始分子分母归并，再计算指标，不拿总订单数判胜负。缺广告对应、缺日、缺指标、实际条件偏差或质量审核变化会限制结论。未出现的搭配保持未知。

CTR 使用 [NIST 介绍的 Wilson 区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。CPA/ROAS 复用固定种子的日区块 bootstrap（4,000 次），结果是近似区间；完全退化的日变化不能证明确定性。所有冻结组和素材构成预先确定的判断集合，用 [Bonferroni 同时覆盖](https://www.itl.nist.gov/div898/handbook/prc/section4/prc473.htm)分配错误率。算法版本、完整输入和输入哈希持久保存，同输入结果相同。

- 业务达标与组间差异分别展示。多个达标广告可同时保留，相对更好也不等于达到业务目标。
- 组间只在数据完整、条件一致、花费比例在预设范围内、且非仅观察分配时比较区间。区间不分离是“差异不明确”，不是等效；即使分离也仅描述实际投放条件下的差异，不作随机因果保证。
- 完整组合测试不把结果归因给角度或单一元素；具体因素测试至多提供条件性关联，不能消除 Meta 分配的混杂。
- CTR 通过不成为经济效果达标。Mock 的所有判断均为模拟，不形成真实效果认识。
- 首轮只确认精确广告。后续 `confirm_combination` 轮需要相同产品理解、组合语义、指标阈值、投放条件、时区和协议，并以不同图片执行、新广告日数据再次达标，才记录该条件范围内的复用支持；不进行跨客群泛化。

同页显示适用条件、数据充分性、业务判定、相对结果和下一步。筛选轮候选进入表达比较，之后确认新执行；已结束小轮的结果、局限和剩余预算进入下一次 AI 策划输入。下一轮仍需用户确认方案和生成费用，不自动追加测试。

结束可为“具体广告有效、组合待确认”“条件下组合复用获支持”“没有达标素材”“证据不足”或“用户停止”。没有充分失败证据不能标为无达标；没有真实达标不能标为广告有效；没有跨轮新执行支持不能标为组合复用完成。总预算或次数耗尽时明确建议收尾；关闭后仅允许追加实际广告对应、报表预检/确认、评估和明确请求的 AI 解读。可显式更正已结束小轮的批次，原批次、旧评估和当时收尾记录不改写，状态不重开；素材审核/改图和新导出仍需新小轮。原有过期解释隐藏，重新解读仍需当前评估与单独费用确认。
