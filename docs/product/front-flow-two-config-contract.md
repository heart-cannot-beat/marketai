# 前台两项配置合同：AI 先出第一稿

状态：Proposed（合并即 Accepted）  
定案日期：2026-10-10  
适用范围：邀请制 Beta 的前台主流程；叠加在 [v9 六区功能对齐验收合同](v9-functional-alignment-acceptance.md) 之上  
相关决策：ADR 0011（前台分层；其 step-up 范围一节已被 ADR 0015 取代）、ADR 0015（MFA 只在登录时验证）

## 1. 目标与原则

v9 六区把"选产品、建维度模板、勾模板、选 Provider、设画幅、生成预览、提交"全部交给用户逐项填写。线上体验（2026-10-10）的结论是：用户不应做任何从 0 到 1 的事。前台只保留两项核心配置，其余由系统完成：

| 核心配置 | 用户提供 | AI 自动完成 | 用户确认 |
|---|---|---|---|
| 设置产品 | 商品链接、图片或一段介绍 | 识别名称、型号、规格、卖点、图片，推荐客群 | 信息是否正确，客群是否合适 |
| 设置广告测试 | 目标；可选已有广告 | 推荐创意方向、测试因素、组合和文案 | 保留哪些方向，微调措辞，确认规模与费用 |

原则（优先级高于页面便利性）：

1. **AI 先给出可用的第一稿**；每个屏幕都是"草稿 + 确认/微调"，不出现空白表单。
2. **用户不接触内部标识**：`lib_`、`prod_`、`libver_`、`gd_`、`gr_`、`av_`、组合签名、T 编号、Prompt 只存在于内部视图。
3. **引导问题最多三个**，每个都有默认值，跳过即按默认执行。
4. **方案以画面示例 + 标题 + "这组在验证什么"展示**，并同时给出生成张数与最高费用。
5. **学习单位仍是维度取值**（蓝图 2026-08-20）：前台简化不得降低 v9 合同的持久化、恢复、租户、成本、防重与 Mock 证据要求。

## 2. 与 v9 合同的关系

- v9 六区（新建生成、素材、投放实验、本地化、放量、创意库）全部保留，降为「高级工作台」：导航折叠，黄金路径 e2e 继续有效。
- 本合同新增的前台页面只**编排**既有领域命令（创意库条目、生成草稿、预览、提交、Run、审核、实验），不绕过它们；AI 起草的内容落为同样的不可变版本与快照。
- v9 §3.1"用户可选择或编辑产品，选择维度取值……"的用户行为由本合同 §3 覆盖：这些动作由系统代做，用户只确认。
- v9 的不变量（§2）一条不变。

## 3. 用户行为合同

### 3.1 设置产品

- 入口是一个粘贴框，接受商品链接、图片（拖放或选择）、一段文字，任意组合。
- 系统在后台 job 中完成抓取、解析与抽取，前台显示"识别中"及可取消。
- 识别结果以**产品卡**呈现：主图与候选图、名称、型号、规格（键值）、卖点（3–6 条）、推荐客群（2–3 张卡：谁 / 为什么买 / 痛点）、外观必须一致项（颜色、形态、logo 位置、接口等，供生成与 QC 使用）。每一项可编辑、可删除。
- 链接包含多个型号时，用户选择具体款；选择后其余型号不进入产品版本。
- 抓取失败（反爬、超时、非商品页）时，前台提示改用"贴一段介绍或截图"，LLM 以 vision 读取截图完成同样的抽取。
- 用户点"确认"即发布产品版本并桥接 `prod_` 记录；AI 提出的 must-match 项带 `proposed_by: "ai"`，确认即 `confirmed: true`（沿用创意库合同 §6）。
- 发布产品不要求登录之后的任何 MFA（ADR 0015）。

### 3.2 设置广告测试

> **已冻结，本节已被取代（#336 维护者定案，#337 实施，2026-11-01）。** 旧测试流程（`/tests`、`app/plans`）只读；新测试在「营销测试」（`/w/{slug}/experiments`）设置。下面的原文保留为历史，不再是现行行为：
>
> - `/w/{slug}/tests/new`（含 `?product=`）服务端重定向到 `/w/{slug}/experiments`，三问与「按默认开始」不再出现。
> - `/w/{slug}/tests/{planId}` 只读：方向卡片、图片、已删方向、规模与张数摘要、Run 与结果照常可看；不能删除、修改、恢复或增加方向，不能改规模，不能「先出样图」或「展开完整测试」，失败的方案不能「重新设置测试」，失败的 Run 不再提示去设置修复。
> - `revise_test_plan` 与 `create_test_plan_run` 对任何调用方（含其他 Workspace、未知 id）返回 410 `legacy_test_plans_frozen`（OpenAPI 标为 `deprecated`）：不写入、不排队 Job、不预留费用、不记审计，只记一行结构化日志。读接口不变。
> - `create_test_plan` 已冻结（#343，2026-11-02）：与上一条相同，对任何调用方（含其他 Workspace、未知产品、同一 `Idempotency-Key` 的重放）返回 410 `legacy_test_plans_frozen`（OpenAPI 标为 `deprecated`），不读取产品，不写入、不排队起草 Job、不预留费用、不记审计，只记一行结构化日志；请求格式不合法时仍先返回 422。#329 之后竞品打标签的词表对每个产品都带表达机制目录，不再依赖旧式方案；已有就绪方案的维度照常进入词表。
> - `/tests` 列表不再折叠「生成默认值」；该编辑器只在 Workspace 设置（§4）。

- 入口在产品卡上；最多三问，均有默认值：
  1. **本次目的**：探索新方向（默认）/ 优化已有广告（列出该产品 Approved 素材与实验 Winner，可勾选，也可上传外部素材，见 §5.2）。
  2. **主要客群**：从产品卡的客群中选（默认第一张）或微调。
  3. **生成规模**：先出样图（每方向 1 张，默认）/ 小测（≤ 12 张）/ 完整测试（≤ 32 张）。
- AI 起草后呈现 3–5 张**方向卡片**：标题、一句"这组在验证什么"、画面描述、文案（标题 + 正文）、折叠的因素与取值；页面底部给出总张数与最高费用。用户可删除方向、修改措辞、增加一条自己的想法；修改后重新规划，张数与费用随之更新。
- "先出样图"提交一个每方向 1 张的 Run；样图出来后用户可删方向，再"展开完整测试"。展开只补生成剩余组合，已成功的组合复用，不重复付费。
- 方向与组合是 provider-neutral 的方案（§5.1）；提交时才绑定 Provider。

### 3.3 结果

> **已冻结，本节部分已被取代（#336 维护者定案，#337 实施，2026-11-01）。** 产品首页不再显示「这个产品我们已经学到了什么」；计划页只读展示这一轮的结果，不再有「导入投放结果」与「按结论生成下一轮」。Run 与素材按方向分组展示以及其中的「回到测试」链接仍保留。下面的原文保留为历史。

- Run 与素材按**方向**分组展示：缩略图网格、标题、这组在验证什么、状态；审核（A / C / X）、导出、去投放实验的出口保留。
- 产品首页常驻"这个产品我们已经学到了什么"：有投放数据时按维度取值给出结论与置信区间；没有时显示人工审核的弱信号，并明确标注"尚无投放数据"。
- 结果页的主操作是"按结论生成下一轮"，它回到 §3.2 并把 winners / losers 的取值标签带入起草。

## 4. 隐藏为默认值的参数

以下参数不出现在主流程，存放在 Workspace 设置的「生成默认值」区块，可改：

| 参数 | 默认值 |
|---|---|
| Provider / 模型 / 执行模式 | 已绑定 OpenAI 凭证 → `openai` / 最新 GPT-Image / `byok`；未绑定 → `mock`，主流程顶部横幅提示去绑定 |
| 画幅 | 按投放位：Feed 1:1、Story 9:16（默认 Feed） |
| 分辨率 | 模型默认 |
| 每组合变体数 | 样图 1；小测 / 完整 2 |
| 组合策略 | 由规划器按规模决定（§5.3） |

## 5. 上游集成硬约束

核心逻辑永远是能与不同上游很好地集成；飞轮的价值在"图出来之后"。

### 5.1 配方 provider-neutral

方案起草的输出是假设 + 因素设计：方向、维度取值、正 / 负英文片段、must-match、参考图、画幅。其中不得含任何 Provider 专属 Prompt。每个适配器自己把配方翻译为调用（纯文本 Prompt、带参考图的 edits、未来其他平台的接口）。`test_plans` 只存 provider-neutral 内容；Run 才绑定 Provider。换上游不改方案，只改执行。

### 5.2 外部素材可进实验

用户在任何上游（设计工具、设计师、真人 UGC）产出的图片必须能上传进来成为候选。上传后由 VLM 按该产品当前的维度词表打标，用户确认后获得与自家生成相同的概念签名，从而可进实验、可被归因。学习单位不依赖"图是本平台生成的"。

### 5.3 规划器确定性

规划器是确定性代码，不是 LLM：样图 = 每方向 1 组合；小测 = 覆盖全部单值并尽量多两两组合，上限 12；完整 = 全因子，上限 32，超出先按模板约束剪枝再覆盖采样。没有测到的组合要在卡片上说明。

### 5.4 下游同理

Meta 是第一个投放平台而非唯一。结果回流（广告级指标与广告 ↔ 素材映射）走适配器；CSV / 手填导入是最通用的适配器，归因与"下一轮"不等自动回流。

## 6. 安全与治理

- **LLM 调用**（识别、起草、打标、QC）走受治理的付费调用路径：durable job、幂等、按 token 上限预估并预留、按 usage 结算、凭证为 Workspace 自己的 OpenAI key；没有凭证时走 mock 给示例并提示绑定。与 ADR 0005 一致。
- **抓取**：仅 http(s)；解析后拒绝私网、回环、链路本地与元数据地址；≤ 3 次跳转；10 s；正文 ≤ 5 MB；图片 ≤ 12 张、每张 ≤ 10 MB；抓取结果作为证据保存并可审计。
- **MFA**：按 ADR 0015，MFA 只在登录时验证。凭证、Meta 连接、数据源、放量目标、花费护栏、Withdraw 这些有外部 / 资金副作用的动作只按角色授权，不再要求 step-up；产品与维度模板的发布只需登录态与 Workspace 成员身份。
- **AI 提议不等于确认**：所有 AI 产出的内容在用户确认前不得成为不可变版本（must-match 的 `proposed_by` / `confirmed` 规则推广到客群、卖点与方向）。

## 7. 验收

1. 空 Workspace 粘一个商品链接 → 30 秒内产品卡 → 确认 → 回答 ≤ 3 问 → 看到 4–6 张样图：**≤ 5 次确认、全程不出现任何内部 ID、不填任何空白表单**。
2. 展开完整测试时，预览的张数等于规划器输出的组合数 × 变体数，已成功的组合不再付费。
3. 导入一份广告级 CSV 后，产品首页出现按维度取值的结论，并能一键生成带该结论的下一轮方案。
4. 上传一张外部图片并确认打标后，它能与自家生成的图进入同一个实验。
5. 抓取私网地址被拒绝并有审计记录；LLM 调用在账本中有预留与结算。

## 8. 明确排除项

- 像素级复刻任何原型；
- 真实 Meta 写入与自动投放（仍按 v9 §7）；
- 多语言 UI（前台文案先中文）；
- 通用的"AI 设计工具"能力：画布、局部重绘、视频——这些属于上游。
