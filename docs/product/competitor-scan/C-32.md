# C-32 竞品看板：缩略图 + 来源 + 链接、筛选、翻转、标签确认、汇总、新快照提示

GitHub #275。Part of Epic #265。Blocked by: C-22 #271、C-23 #272、C-31 #274。大小 L。前端，只在 `web/components/competitors/` 加组件。

## 范围
1. 观察卡片（规格 §9）：512px 缩略图（视频显示封面帧并标“视频”）、广告主、在投天数、形式、标题、CTA、相关性标记、标签建议；**每张缩略图下固定显示“来源：Meta Ad Library”与原始链接**；素材不可用时占位 + 链接。
2. 筛选：竞品（含自家单独一组）、相关性（相关 / 相邻 / 无关）、在投天数（≥30 / ≥60 / ≥90）、形式。
3. 翻转相关性；确认 / 修改标签；两者都显示修订历史；“重新冻结”（免费、确定性）与“重新聚类”（付费，先显示报价再确认）两个动作。
4. 汇总区：购买主张簇（几家、几条、最长在投）、“未归类”观察、相邻观察、长跑广告、自家对照、AI 一句话结论（标“AI 推测”）；产品设置“起草时使用竞品快照”开关（默认开；存储与写接口由 C-23 提供）；读取投影 `competitor_snapshot_stale` 为真时显示“有新的竞品快照，重新起草可采用”。
5. 缩略图不可下载、不可拖入参考素材、不出现在导出包；复用 `board_thumbnail_refs` 的签名方式，签名短时效。

## 验收
- 规格场景 7、8、14、15 的界面部分。
- e2e：Mock 扫描后翻转一条、确认一条标签、重新冻结（“未归类”出现）、重新聚类（报价 → 确认 → 新簇），汇总数字随之变化；关掉开关后新起草的方案不带 `competitor_snapshot_id`；新快照提示出现与消失。
- 手机 390×844 下卡片可读，来源标注不被截断。
