# C-21 扫描任务：报价、预留、状态机、续跑与对账、Worker fetch + media

GitHub #270。Part of Epic #265。Blocked by: C-11 #267、C-12 #268、C-13 #269。大小 L。含迁移与 OpenAPI。

## 范围
1. 表：`competitor_scans`（含 `status`、`stage`、`initial_credential_version_id`、`params_json` 含 `language`、`max_tagged_ads`、`max_discover_advertisers`）、`competitor_ads`（不含竞品归属列，归属由来源行投影）、`competitor_ad_origins`（规格 §11）；后两张追加只读。
2. API（`/api/v1/competitor-scans`）：
   - `preview`：参数 → 两行报价（供应商额度与 USD；LLM 上限 = 按规格 §5.1 的调用名清单逐个 `quote_llm_chat` 之和）、需要的凭据；只接受已确认竞品；缺 `market_data` 或 AI 凭据任一项时只返回 Mock 选项，不混用。
   - 创建（`Idempotency-Key` 重放，不按日期去重）：两项在同一 Operation 下原子预留：供应商额度一笔，LLM 按调用名 `filter:i` / `tag:i` / `cluster:1` / `discover:i` 用现有 `reserve_llm_chat` 逐个预留到上限，任一失败整体拒绝；Spend Guardrail 对合计生效；未用的调用名在扫描结束时释放。这些调用名就是 C-22 / C-23 / C-33 执行与重放时使用的名字（规格 §5.2，序号名贯穿），本 Issue 不得另起名。同一凭据版本的解析 / 扫描 / 续跑在 Workspace 内串行，后来者排队并记录等待。
   - 读取（含分步证据、两项成本、状态与 stage、凭据版本记录）。
   - `resume`：`partial` / 402 `failed` 续跑，同一扫描 ID，从已存 cursor 继续，只对剩余页数与剩余 LLM 步骤报价与预留；沿用原 Job 时按原调用名重放，新建 Job 时只为尚未尝试过的序号预留，已有答案的序号读取证据、不再预留（规格 §5.1）；可用新凭据版本，记入 `evidence_json.resumes[]`。
   - `reconcile`（Owner）：对 `uncertain` 页手动标记“已扣 / 未扣”。
   - 列表观察（分页、筛选：竞品含自家、在投天数、形式），返回来源列表。
3. 状态机：`queued → running → completed | partial | failed | uncertain`（定义见规格 §5.1）。
4. Worker `competitor_scan.run`（规格 §5.2）：
   - **fetch**：先全部主页、再关键词；每页一个 ProviderCallAttempt + dispatch fence；cursor 入证据，断点续拉；供应商 4xx（非 429）终止该竞品；429/5xx 重试 2 次后该竞品失败；fence 后中断 `uncertain` 不重发；按 `credits_charged` 结算；402/401/403 终止扫描并释放未用预留。同一 `ad_archive_id` 只插入一行，任何来源（含续跑补拉的主页来源）都只追加 `competitor_ad_origins`；观察属于哪家竞品由来源行投影。
   - **自动对账**：续跑开始先免费调用 `credit-balance`，与 `uncertain` 页之前最后一次成功调用的 `credits_remaining` 比较：差 0 → 未扣，差 1 → 已扣，其他（含该记录来自 `cached` 响应）→ 停在 `uncertain` 留给 `reconcile`。对账不恢复响应，该页按新尝试重拉。
   - **media**：下载 `original_image_url` 与 `video_preview_image_url`，sha256 去重，purpose `competitor_media`，派生 512px；记录去签名来源 URL、抓取时间、hash、大小、类型、过期时间；403 → `ad_refresh` 补拉（付费，fence，计入配额），超配额标“素材不可用”。
   - 每步 `evidence_json[step]` + `competitor_scan.step` 审计事件；网络与 blob I/O 不持有事务。
5. filter / tag / cluster / freeze 在本 Issue 以 `skipped: not_implemented` 记录，扫描仍到 `completed`；LLM 预留在这些步骤未实现时，于完成后按调用名逐个释放；由 C-22、C-23、C-33 填充，它们负责写入各步的 `evidence_json[step].assignments`。
6. **OpenAPI 先行 PR**：先合契约与 allowlist（供 C-31 提前开工），再合实现。

## 验收
- 规格场景 3、4、5、6、10、13、16。
- 正向：Member 可以发起扫描与续跑；zh-CN 用户发起的扫描 `params.language=zh-CN`。负向：跨 Workspace 读扫描 / 观察 / 对账 404；未确认竞品不能进入 preview；缺任一凭据时 preview 只给 Mock；同一 `Idempotency-Key` 重放返回同一扫描；非 Owner 调 `reconcile` 403。
- 用 Mock 夹具跑完整扫描：3 家 × 3 页 + 2 个关键词，观察数与夹具一致，无重复 `ad_archive_id`，关键词与主页重合的广告有两条来源行；让一家竞品在首轮 429 失败、关键词先落库，续跑后该竞品的广告只追加 `page:` 来源行并在投影里归入该竞品；对 `competitor_ads` 的 UPDATE 被触发器拒绝且流程不需要它。
- 调用名：受理时预留的调用名集合与规格 §5.1 / §5.2 的清单逐字一致；扫描结束时，所有未用序号的预留都被释放，没有残留的 open 预留。
- 对账测试：差 0、差 1、差 2、负数、来源为 cached 五种序列，前两种自动结算，后三种停在 `uncertain`；两次扫描同时发起，第二次排队。
