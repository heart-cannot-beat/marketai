GitHub #271。Part of Epic #265。Blocked by: C-21 #270。大小 M。含迁移与 OpenAPI（在串行链内）。LLM 费用已由 C-21 的扫描报价统一预留，本 Issue 只消费该预留。

## 范围
1. 表：`competitor_ad_assessments`（kind=`relevance`），追加只读。
2. 规则前置（规格 §7.1）：落地页为 `facebook.com` 个人账号、批发站（`alibaba.com` 等可配置清单）、分类为经销商/车行的广告主直接 `unrelated`，不送 LLM。
3. Worker **filter** 步骤：受治理 `llm_chat`（文本），按 `collation_id` 合并变体后每批 20–30 条；输入标题、正文、`link_description`、落地页路径、广告主分类 + 产品理解的 `category_need`、`product_name`、`situations`；输出 `relevant | adjacent | unrelated`、置信度、一句理由；提示词与输出语言用扫描参数 `language`（发起者的界面语言，由 C-21 冻结）；调用名是 C-21 预留的 `filter:i`（规格 §5.2）：首次调用前把批次划分冻结进 `evidence_json.filter.assignments`，按 `(Job, "filter:<i>")` 重放，不重复付费；用不到的序号在本步结束时释放。
4. API：翻转（Member 可操作，写入新修订）、按相关性筛选观察、读取判断历史。
5. 受控 Mock 的 LLM 夹具：Halcyon Motors 自动驾驶 → unrelated，Kestrel Power V2L → adjacent，Northpeak → relevant。

## 验收
- 规格场景 7（前半：无关不产生视觉打标调用，由 C-23 验证后半）。
- 翻转两次回到原值仍是两条新修订，历史可查。
- 批次重放：Worker 重投递不新增 LLM 调用记录。
- 负向：跨 Workspace 翻转或读取判断返回 404；Owner 与 Member 都能翻转，审计记录操作者。
