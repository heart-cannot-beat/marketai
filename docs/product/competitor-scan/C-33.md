# C-33 竞品发现：关键词 → 广告主聚合 → 推荐接受 / 拒绝

GitHub #276。Part of Epic #265。Blocked by: C-21 #270、C-22 #271、C-24 #273、C-31 #274。大小 M。含迁移与 OpenAPI（串行链末位，在 C-24 之后）。

## 范围
1. 表：`competitor_discovery_decisions`（规格 §11），追加只读。
2. 扫描参数中的关键词走 `search_ads`（每词默认 2 页，`keyword_page` 计费），在全部主页拉取之后执行；观察 `competitor_id` 为空，来源行为 `keyword:<词>`；与主页重合的广告只追加来源行。
3. 规则前置过滤后按广告主聚合，最多取 `max_discover_advertisers` 家（默认 30，按观察数排序）；LLM 判断“该广告主是否销售同品类产品”（相关 / 相邻 / 无关 + 理由），输出语言用扫描参数 `language`，费用已含在 C-21 扫描报价的 discover 项里；调用名是 C-21 预留的 `discover:i`（规格 §5.2）：首次调用前把“序号 → 广告主”对应表（观察数倒序、再按 `page_id`）冻结进 `evidence_json.discover.assignments`，按 `(Job, "discover:<i>")` 重放；对应表之外的序号在本步结束时释放。
4. 推荐 API 与界面（`web/components/competitors/` 内）：广告主、分类、观察数、落地页域名、理由；“接受”走 C-13 的确认卡片（page id 来自广告，不发起解析任务、不付解析费）；“拒绝”写入决定表，后续扫描不再推荐；已是竞品的广告主不推荐。
5. 个人账号的广告按 `unrelated` 处理且不展示头像（规格 §10）。

## 验收
- 用 P0 夹具：推荐出 Northpeak、Lumenline、Kestrel Power；车行、批发站、个人账号不出现在推荐里。
- 接受后下一次扫描按主页拉取该竞品，证据中无 `page_search` / `probe` 调用；拒绝后再次扫描不再出现该广告主。
- 负向：跨 Workspace 读推荐或写决定返回 404；Member 可接受与拒绝，审计记录操作者。
