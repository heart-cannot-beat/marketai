# 营销 QC：AI 自动检查，人工确认与微调

状态：新版已上线，用真实客户产品做的生成/QC/修订/人工确认/导出另有验收记录（在私有仓库，不在本仓库）。2026-10-17 补齐已发布实物参考图选择及来源确认，同一冻结版本用于生图、QC 与反馈修订。AI 提供建议，用户确认和微调。2026-10-25 起拆成单图检查与对照检查（#229，规格 §9.1）。2026-10-26 起检查结论与结果解释按轮次方案的策略语言书写（#254，ADR 0013）。2026-10-27 起单图检查在同一次调用中逐字转写图中标题与正文，由服务端与已确认文案比对（#294）；被拒收的模型输出保留原因与有界原文（#295）。

## 用户流程

1. 一张图生成成功即可进入单图检查（`single`），无须等待整批：页面展示「检查已生成的」对象、视觉供应商/模型和费用上限，用户确认费用后后台分别检查每个精确版本。
2. 看板为每张图指定的比较对象（`compare_with`）都有可用图片后，才能运行对照检查（`paired`）；缺对象时显示「等待某组图」，不能冒充通过。两类分别报价、预留和结算。
3. AI 读取实际图片、配套文案、已确认事实、购买主张、表达和（对照检查时）具体对照版本，自动填写检查结果、画面依据、理由、信心与修改建议。两类结果分开显示，通过项默认收起，疑点优先显示。
4. 用户集中确认符合要求的素材，每张图需要单图与对照两类当前结果；也可展开单条调整建议，修改 AI 判断时填写依据。正常路径不要求重新填写所有检查项。需要时仍可显式选择人工审核后备路径。

5. 需要修正时直接准备反馈草稿，AI 疑点及已保存的人工意见自动带入；可以补充微调，准备草稿不产生图片费用。原版本保留，确认生成费用后产出新版本，两类检查都对新版本重跑并重新人工确认；旧检查记录保留可查。冻结后的投放清单不能原地换图。

AI 结果不是人工批准，更不构成投放有效证据。只有用户确认才写精确版本 QualityReview 和营销审核记录，并进入原有导出门禁。批量操作遇到未解决问题整批拒绝，不静默跳过失败项。

## 检查与证据范围

- 单图检查：文件有效（系统解码与哈希核对，不是视觉通过）、产品可见表现、广告语言、文字可读性、事实支持、品牌风格、购买主张、表达落实和图文一致，以及组合自带的意图检查。
- 对照检查：属于原定角度/表达（`belongs_to_intended_combination`）、同角度不同表达在画面中确有区分（`expressions_distinct`，仅当方案的比较范围包含同角度其他表达时）、该变的变了/该保持的保持（`comparison_faithful`）。输入为待检图与看板 `compare_with` 中每个对照组合最早的可用版本，同角度其他表达优先，最多四张；超出的组合在输入中写明未发送。方案在表达三要素之前冻结的轮次不增加前两项。确认时沿用这些具体版本，具体因素测试导出必须包含所核对的版本。
- 单图通过不能代替对照通过：审批需两类当前结果，缺少一类时只能人工覆盖并写明依据。拆分前一次性完成的检查（`kind` 为空）保留可读，按其原输入判断是否仍为当前结果，并同时计作两类。
- 受众和投放时期等不可见条件仍在 Meta 广告对应时确认，视觉检查不会把它们标成已经核验。
- 没有真实产品参考图时，其他生成图不能充当外观真值。现在可选择最多三张已发布、有有效使用权的实物参考图，记录准确产品/变体、来源与人工身份确认。检查输入保留版本与哈希；参考图不是认证或隐藏性能的依据，也不能替代广告间的具体因素对照。未选择参考图时 AI 不会自动确认产品身份；可将仅剩外观待确认的素材集中核对一次。清楚观察到的产品错误仍保留失败，不能被“缺少参考”降为可整批忽略的疑点。
- 低信心、没有支持事实或没有必要对照时保留 unknown。事实引用只允许已确认事实 ID；不接受推测作为事实依据，不接受遗漏、重复或额外检查项。
- 真实验收发现模型可能用“产品名称”支持画面中的认证和参数。补充 `marketing-evidence-gates-v3`：对检查中观察到的常见认证编号、量化参数和价格，核对所引用事实是否包含对应声明；不支持时保留模型原判但将有效判断设为 unknown。不会把 1500 A 当作 500 A 的依据。这是保守的附加门禁，并不声称能够证明所有语义关系。
- 图中文案不由模型自由判断（#294，`marketing-vision-qc-single-v3`）：同一次单图调用先把图中实际渲染的标题与正文逐字写入 `rendered_text`（错字照抄，看不清或没有时为空字符串），不增加调用次数。服务端在 `normalize_report` 中把它与该组合已确认的 `headline` / `body_copy` 比对，忽略大小写、空白和 Unicode 标点（`%` 例外，仍需一致）：任一字段不一致时 `copy_consistent` 判 fail（`gate_reason=rendered_text_mismatch`），`rendered_text_diff` 记录字段、已确认文本、图中文本和逐词差异（中日文按字），修改建议列出 “Vortes” → “Vortex” 这样的改正；转写缺失时，模型的 pass 改为 unknown（`rendered_text_missing`），模型自己的 fail 保持不变。转写一致从不把其他判断升为 pass。人工审核仍可改判，覆盖记录冻结差异与理由。Mock 占位图没有文字，转写为空，因此文案检查保持 unknown。
- `summary` 是模型自己的话：只有全部检查为 pass（`quality_suggestion=ready_to_confirm`）时界面才把它当结论显示；任一项 fail 或 unknown 时改为服务端按检查结果计数的状态句（未通过 / 待确认 / 通过各几项），不显示模型 summary，审核备注也不再用它预填。记录中的 summary 保持原样。
- #294 之前的 `marketing-vision-qc-single-v2` 调用按自己的策略重建输入（提示词与 Schema 字节不变），因此仍是当前结果，按原样显示、不做比对，也不会为补转写重新收费；新图与修订版用 v3。对照检查（`marketing-vision-qc-paired-v2`）的 Schema 不变，带 `rendered_text` 的对照输出会被拒收。证据门禁版本升为 `marketing-evidence-gates-v4`。
- 已保存的模型输出可重新应用确定性证据门禁，不重发付费请求。原始模型回执保持不变；人工确认记录另冻结有效检查结果、门禁版本和调整依据。
- AI 报告与人工判断分开保存。批量共同确认只能解决公共基础检查的 unknown；AI 标为 fail 的项目必须单独查看并明确调整理由，不能用批量勾选跳过。不同组合的 intent_n 不支持共同覆盖。

明确选择 Mock 时只替代外部视觉服务，输出清楚标记为受控模拟，不把占位图当成视觉通过。真实检查失败不会自动回落 Mock。

## 输出语言

- 单图与对照检查的 summary、画面依据、理由和修改建议，以及证据门禁写入的修改建议、文件检查和集中确认的默认备注，按轮次快照中方案的 `strategy_language`（`en-US` / `zh-CN`）书写；方案没有该字段时用请求方界面语言（报价 `strategy_language` 参数、启动请求体同名字段），两者都没有时沿用旧的中文。结果解释的证据目录同样按该语言生成，模型仍只选择证据和解释键。
- 两种语言的提示词逐句对应、规则一致，检查项的 key、单图/对照划分和输出 Schema 不变；英文提示词明确要求用英文书写，引用的可见文字、品牌名和型号保持原样。
- 语言写入冻结输入并进入 `input_hash`，因此同一张图换语言检查是一条新的、需报价和预留的调用；已有当前结果不会为了翻译而重新收费。调用与解释记录保存其语言，界面语言不同时只加一行「以某语言生成」提示，不自动翻译，也不改写历史证据。
- #254 之前的记录没有 `strategy_language`，按原中文提示词重建输入并保持原 `input_hash`，因此仍是当前结果，并以 `zh-CN` 显示。读取轮次或工作流时带 `include_languages=true` 才返回调用与解释的 `language`。
- 审核界面按 `check_id` 显示检查项名称（#308）：标准检查项（`CHECKS` 的 key 和 `file_valid`）显示界面语言文案，英文文案与 `CHECKS` 原文逐字相同；`intent_n` 显示方案原文。`required_checks` 中的英文标准是 AI 的检查依据，会进入 `input_hash`；审核记录、AI 调用输入和导出中的这些原文都不改。

## 配置与费用

API 与 Worker 使用相同配置：

```dotenv
MARKETAI_MARKETING_QC_PROVIDER=openai
MARKETAI_MARKETING_QC_MODEL=gpt-4.1-mini-2025-04-14
MARKETAI_MARKETING_QC_MAX_COST_USD=0.10
```

支持 Gemini 与 OpenAI 的视觉协议。最大费用为每条检查的大于零、不超过 10 USD 的部署报价，必须覆盖实际图片和输出上限，不是内置供应商现价。Workspace 需要该供应商的 `binding_scope=generation` 凭据、有效生成权益和 USD Spend Guardrail；不会借用全局 Key 或其他 Workspace 凭据。

上述固定版本及单条 0.10 USD 配置已用于当前线上 API/Worker，整批仍先预览并显式确认。参考图选择不自动产生模型调用，本次扩展没有追加真实付费检查。

费用依据于 2026-10-17 重新核对：官方 [GPT-4.1 mini 模型页](https://developers.openai.com/api/docs/models/gpt-4.1-mini)确认 `gpt-4.1-mini-2025-04-14` 支持图片、Responses 和结构化输出；[标准价格](https://developers.openai.com/api/docs/pricing)为输入 0.40 USD / 百万 tokens、输出 1.60 USD / 百万 tokens。按[视觉输入规则](https://developers.openai.com/api/docs/guides/images-vision)，32px 分块乘数为 1.62；本地最长边 2048 的每张图最多 4096 个分块，保守计 6636 输入 tokens。六张图与 96,000 字节完整文本合计约 135,816 tokens，另留协议余量后按 160,000 输入 tokens 与 8192 输出 tokens 预算，上界约 0.0772 USD，现有单条 0.10 USD 报价仍覆盖。该推算只适用于固定模型、当前图像预处理与标准服务档位，不能套用到其他模型或新价格。请求显式使用 `service_tier=default`，不自动切换加速档位；账本按上限保守估算结算，报告另存供应商请求编号与实际 token 回执，不把估算声称为供应商账单。

每类一批最多 60 条检查。单图检查每条最多一张目标图、三张实物参考图和一张品牌 Logo；对照检查每条最多一张目标图和四张对照图；拆分前的旧检查为一张目标图、两张对照图和三张参考图。每条不超过六张；原文件每张最多 20MB、16MP，输入采用固定规则处理为最长边 2048 的 JPEG，每张编码结果最多 2MB，保留源文件哈希、派生哈希、尺寸及转换版本。完整文本输入含 Schema 最多 96KB，输出最多 8192 tokens，报告内容有额外长度限制。最大费用必须覆盖这些边界。

按类型预览整批费用后再提交。服务端重新计算对象、检查上下文与报价，原子预留成本，并使用现有费用账本按上限估算结算或释放。重复请求不重复创建调用；已完成且上下文一致的检查不会重复收费。图片不可用或调用前资格变化会释放未调用预留。未知网络结果保留费用暴露，禁止自动重新发送；已知失败后重试是一次新的显式付费意图。

当前迁移头为 `zy0f1a2b3c4d`；本次参考图不新增数据库结构。已有 `u1a2b3c4d5e6` 迁移新增 `marketing_creative_reuses` 将本产品的历史图片精确版本关联到冻结组合；只增加关联，不改写原生成模式、来源或生成意图，不继承旧审核。API `POST /marketing/rounds/{round_id}/creatives/reuse` 使用原有 If-Match 和幂等规则。跨租户、跨产品、真实/模拟混用、同版本改归属、缺少已提交文件均拒绝。关联来源、原 prompt、当前意图和图片哈希进入 AI 输入与导出清单。历史资产若已保存 committed key / storage version，读取使用该精确指针和内容校验；新生成仍兼容已有响应事件中的存储版本。

检查冻结精确图片、配方、文案、事实、对照版本、完整系统提示词、输出 Schema、模型、策略和输入哈希。AI 与人工修改记录均可回溯，过期结果不能用于确认。已审核历史素材的旧人工含义继续保留。

Worker 先读取并校验实际存储版本，再提交付费调用边界，之后才发送多模态请求。调用边界后中断的恢复只标记结果不确定，不重复发送。晚到的已知响应可以结算并保存原调用结果；不会自动批准素材。图片数据通过 Worker 直接发送到所选视觉供应商，不把客户指定 URL 交给模型抓取，不经 Next/FastAPI 中转图片字节。

接口：

- `GET /marketing/rounds/{round_id}/ai-qc/quote?kind=single|paired&strategy_language=en-US|zh-CN`：该类待检查对象、费用及等待对照的图片（`waiting`）；不带 `kind` 时为旧形状的单图报价；`strategy_language` 仅在方案没有策略语言时使用。
- `POST /marketing/rounds/{round_id}/ai-qc`：确认某类报价（`kind`，默认 `single`；`strategy_language` 同上）、排队整批检查，使用 If-Match 和幂等键。
- `POST /marketing/rounds/{round_id}/ai-qc/confirm`：集中确认，每张图需同时给出单图与对照结果，记录公共待确认项的人工依据。
- 原 `reviews` 接口支持 `ai_qc_id`（单图）、`paired_ai_qc_id`（对照）和 `override_note`，关联 AI 证据及单项调整。
- 读取轮次或工作流时带 `include_qc_kinds=true` 才返回 `paired_ai_qc`、调用 `kind` 与看板的 `single_qc_*`/`paired_qc_*` 阶段；旧 BFF 读取保持拆分前的形状。
- 带 `include_qc_evidence=true` 才返回结果的 `rendered_text`、检查项的 `rendered_text_diff`（含人工审核冻结的有效检查结果）与调用的 `error_detail`；不带时 fail / unknown 结论相同，只是不含这些字段。

图片输入和结构化输出协议依据 [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision)、[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Gemini generateContent](https://ai.google.dev/api/generate-content)。部署方仍须核实所配置模型与账户支持情况。
