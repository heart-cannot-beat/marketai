# Adopt a versioned OpenAPI BFF seam for the SaaS UI

The BoxyHQ/Next.js Web, FastAPI Domain API, and Worker will live in one repository but remain independently built and deployed Implementations; the authenticated SaaS UI will address every business page under `/w/{slug}`, call only a same-origin allowlisted BFF Adapter under `/api/domain/v1`, and let that Adapter resolve the Workspace, verify the active membership, mint a per-request ES256 delegated-user token lasting no more than 60 seconds, and forward to the private versioned FastAPI Interface without reading domain tables or reproducing domain rules. FastAPI OpenAPI is the sole remote contract and generates the server-side TypeScript client with CI drift and breaking-change checks; long-running or side-effecting commands use durable Operation resources and idempotency keys, mutable aggregates use revision preconditions, errors use Problem Details with stable codes, and private binaries cross a `BlobStore` seam through authorized short-lived signed URLs. We accept the cost of a full six-area Next.js rewrite and an atomic cutover from the frozen `static/` UI because extending or dual-writing the legacy browser would preserve an untrusted client state model and create a second integration surface; we reject browser-held domain tokens, direct FastAPI access, a generic open proxy, Server Actions as a second domain API, BFF domain persistence, lockstep deploys, and Next.js binary relay because they weaken tenant isolation, contract ownership, compatibility, or operational depth.
