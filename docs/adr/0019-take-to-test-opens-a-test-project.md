# ADR 0019: 拿去测试新开一个测试项目

**Status:** Proposed (Accepted on merge)  
**Date:** 2026-11-21  
**Decided in:** #245（维护者决定，2026-11-21）  
**Amends:** [营销测试规格](../product/ai-marketing-testing-spec.md) §6、§8（只对新开头的测试）  
**Relates to:** [ADR 0018](0018-ads-before-test-setup.md)（广告内容先于测试设置）、[ADR 0005](0005-separate-commercial-access-usage-and-provider-cost.md)（访问、用量与 Provider 成本）、[ADR 0009](0009-three-meta-evidence-modes-and-platform-workspace.md)（Meta 证据的三种模式）

## 背景

ADR 0018 让新产品先有广告：用户读完产品就能看到广告草稿，核对后留下几张。第 1 步到“下载图片”为止。要拿这些广告去投、拿数据回来，用户现在得回到改版前的页面，从头读一遍产品、确认一份和这些广告无关的整份方案。

现有的小轮（冻结、质量审核、交接包、对上 Meta 广告、传报表、评估、结束）是成熟的，第 3 步的结论、本地化和放量也都从小轮的评估拿证据。但冻结小轮要求项目处在“方案已确认”状态，而广告想法项目没有方案；把它改成“方案已确认”，按 ADR 0018 的规则所有广告都会变成需要重出。

设计见 [第 2 步设计](../superpowers/specs/2026-11-21-ads-first-step-2-take-to-test-design.md)。

## 决定

1. **每次“拿去测试”新开一个测试项目。** 在同一个产品下新建一条营销项目，`flow = "ads_test"`，记下它来自哪个广告想法项目。它一建出来就是“方案已确认”，方案只由“开始测试”这一个命令写入；改版前的改方案、重新起草、改产品理解、按方案出图的接口对它一律不可用。广告想法项目本身不变。
2. **方案按模板生成，不调 AI。** 比什么由留下的广告决定（跨两个以上主张比主张，同一主张两种以上讲法比讲法，只有一张就只看是否达标），比较方式是整组广告比，结论范围是这几张广告。用户回答的三个问题和改过的默认项写进方案。生成的方案必须通过现有方案的全部校验，不放宽。
3. **留下的广告原样挂进小轮。** 用现有的复用记录，记明来自哪个广告想法项目、哪张广告；冻结的组合就是广告出图意图里的组合。能不能进广告包按 ADR 0018 的导出条件判断。
4. **“一起看”的检查照旧要求，付费，费用写在按钮上。** 小轮要求、单图自动检查没做的那几项，冻结之后用现有的小轮 AI 检查做，由 API 受理。质量审核只写这一轮自己的记录，每一项通过都带依据；不写工作区共享的审核链，改版前测试的审核结果因此不变。
5. **同一个产品同一时间只有一个进行中的测试。**
6. **数据回来的新规则只用在测试项目的轮次上：** 用户每次传“从开始到今天”的完整报表，后传的覆盖重叠的日子；不属于这一轮的行只存不算；按广告名里的短键预填对应，确认一次全部生效；第一次确认报表之前可以改开始日期；提前结束按结束那天算；任何时候都能补记偏差。这些都追加记录，冻结的快照不改写。
7. **测试开始后再改广告想法，正在跑的测试不受影响。** 评估和广告包按开始那一刻的内容；测试页提示哪些广告后来被改了。

不变的：

- 改版前的测试（`flow = "plan_first"`）和广告想法项目（`flow = "ads_first"`）的状态、接口、页面、上传和评估规则都不变。
- 评估规则（判断协议、成熟判断、判定）不变；7 天测试按现有规则在开始后第 16 天出结论。
- 付费工作由 API 受理；让 Worker 受理付费工作的例外仍只限首批（ADR 0018、费用合同 §11）。
- 报表仍由用户上传，ADR 0009 不变；Meta 写入保持关闭。
- 不可变版本与只追加证据、租户隔离、主流程不出现示例数据，这些不变量全部适用。

我们没有选的：

- **在广告想法项目上直接加测试。** 小轮代码到处默认项目是改版前的，改动最多、最容易碰坏旧测试；冻结和改广告想法要对同一个版本号，测试在跑时一改就冲突。
- **给新开头另做一套测试。** 小轮的生命周期要重写一遍；第 3 步的本地化、放量要从小轮拿证据，还得再搭桥。
