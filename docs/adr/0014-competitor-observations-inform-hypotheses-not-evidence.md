# 竞品观察只能启发假设，不能充当事实或投放证据

我们决定把同品类竞品在目标市场的公开在投广告引入产品理解与方案起草，作为一类新的记录“竞品观察”：带来源供应商、抓取时间、凭据版本与原始响应引用的外部可见事实，回答“别人在讲什么、讲了多久”。它与产品事实、AI 推测、投放验证结论并列保存，不互相转换：竞品的声明不能写成本产品的事实；AI 对竞品观察的相关性判断、维度标签与“拥挤 / 空白”归纳一律属于 AI 推测，用户确认只改变采纳状态，不改变证据性质；一条广告在投时间长只说明广告主仍在付费，不进入投放验证结论、学习快照或任何归因，也不得被解释成“该角度有效”。

竞品观察不是外部素材，也不是参考素材。它没有上传门禁与权利声明，不能进入实验、创意库、本地化与放量，不能作为生图参考或 Prompt 片段，不能被导出；素材存档只为 Workspace 内展示与视觉打标签，随 Workspace 删除级联清理。起草时 planner 只收到按角度归纳的文字摘要，并受“不得复用竞品标题、正文与画面描述”的约束；由此产生的 `competitor_crowded` 与 `competitor_gap` 只是 advisory，不阻塞确认，也不自动提升或降低任何角度的优先级。

扫描是付费外部调用，完整沿用 ADR 0005：凭据由 Workspace 自带（新增作用域 `market_data`），先报价、原子预留、每页一个 ProviderCallAttempt 与 dispatch fence，按供应商返回的 `credits_charged` 结算，未配置凭据只能走受控 Mock 且不得在失败后静默切换。供应商选型与调用链路不经过任何聚合网关：我们接受直接对接单一供应商（ScrapeCreators）与 Meta 改版导致抓取失效的风险，以换取每条观察可追溯到具体供应商、凭据与请求的能力；备选供应商通过同一 `AdLibrarySource` 抽象接入，由用户显式选择，不自动回退。

方案版本引用冻结的竞品快照 ID，重扫产生新快照而不改写旧方案；主页身份、相关性与标签的每次确认或翻转都是追加修订。具体合同见[竞品广告扫描规格](../product/competitor-scan-spec.md)。此 ADR 不改变 ADR 0007 的版本边界与 ADR 0010 的问题 / 证据边界，也不把“竞品没讲”提升为可测试假设之外的任何结论。
