# 显式交接有边界的营销证据，复用既有下游门禁

新营销评估经用户确认准确 ProductVersion、OfferVersion 与实际测试条件后，才创建独立、可追溯的下游兼容记录；其算法来源始终为营销评估，不能解释为旧实验相对 Winner，更不能回写旧结论。本地化仅接受真实回传支持的精确达标素材，放量候选进一步要求不同执行和另一小轮支持的组合；用户 CSV 的来源仍为用户提供，不能冒充 Meta 独立核验。

我们接受在既有决策、确认及冻结版本结构中保存专用兼容记录，以复用本地化真值、质量、权利与放量 delivery 血缘约束，避免新建一套宽松旁路；每次下游检查还必须重新验证营销评估、有效回传批次、精确素材审核及支持轮次，数据更正或撤回会使旧交接失效。旧实验按原算法保留，所有交接只产生准备和建议，不产生 Meta 写操作。

没有独立落地页版本实体时，新营销交接使用明确声明精确落地页 URL 的不可变 OfferVersion 作为下游落地页版本指针，并另外保留 URL 证据哈希；这样满足真实 Library 外键，而不创建以哈希冒充版本 ID 的记录。每次交接检查都重验指针与销售方案及测试 URL 一致，旧实验保留原标识行为。
