# 先看广告，再定测试：营销测试开头重排（设计）

- 状态：已确认（产品负责人，2026-11-16）。规则变化记在 [ADR 0018](../../adr/0018-ads-before-test-setup.md)。第 1 步的分块见 #187，逐步计划见[第 1 步实施计划](../plans/2026-11-16-ads-first-step-1.md)。产品负责人明确定过的四件事：做法选 B（§4），仍然先配 Key（§8），去掉没有 Key 时的 Mock 体验（§5.7），竞品从出广告的流程里拆出来（§5.6）。
- 日期：2026-11-16
- 范围：从“贴产品链接”到“看到结论”的主流程，以及它带来的导航变化：左边栏、总览、产品资料、竞品独立、现有功能的去向。分三步交付，本文对第 1 步写到可以排实施计划的程度，第 2、3 步写到行为层，动手前各自再细化一次。
- 相关：[营销测试规格](../../product/ai-marketing-testing-spec.md)、[交接与回传](../../product/ai-marketing-delivery-loop.md)、[前台两项配置合同](../../product/front-flow-two-config-contract.md)、[竞品扫描规格](../../product/competitor-scan-spec.md)、ADR 0005、0009、0010、0011、0013、0014。
- 示例一律使用虚构品牌 Acme Charge 和 `*.example` 域名。可点击的设计稿在仓库之外，以本文的文字和示意为准。

## 1. 为什么做

产品负责人的判断：现在的产品太复杂，对用户不友好，而且“从一开始就很复杂”。

查代码和文档后，开头重的原因有五个：

1. **看到第一张图之前要过很多关。** 现在的顺序是：录入产品并确认产品卡 → AI 整理产品理解，用户逐条确认事实 → AI 起草测试方案，用户确认整份方案 → 预览生成费用并确认 → 出图。方案里包含预算、目标成本、落地页、停止规则等二十多项。
2. **根因在数据结构。** 测试方案（`TestPlan`）是一份文件，既装广告内容（主张、讲法、文案、画面说明），也装测试设置（预算、目标、周期、判断规则）。系统规定整份方案确认后才能出图（`generation_drafts` 要求 `plan_confirmed`）。所以只改界面做不出“先看图”。
3. **同一个产品要读两遍。** 产品页的录入产出“产品卡”，营销测试又单独产出“产品理解”，用户各确认一次。
4. **可能要配两个 Key。** 产品录入只认 OpenAI Key，策划认部署配置的那一家（Gemini 或 OpenAI），出图另有三家可选。新用户不知道该配哪个。
5. **内部的严谨直接成了界面文案，入口又多。** 页面上有“Controlled Mock”“Deterministic check”这类词；导航有十个入口；v9 六区、已冻结的旧测试流程、现在的营销测试三代并存。

一句话意图：**新用户贴一个产品链接，几分钟内看到自己产品的广告草稿；决定要投的时候，才回答和投放有关的问题。**

## 2. 目标、不做、不能变成的样子

### 目标

1. 从贴链接到看到第一批广告草稿，用户只提供链接（或介绍、图片）和投放市场，之后不需要再点任何东西。唯一的费用确认是开始按钮上写明的最高费用（见 §8）。工作区还没有 Key 时，在同一个画面里贴一次 Key。
2. 每个问题等到用得上的那一刻才问。
3. 主流程用普通人能懂的话（§9 用语表）。
4. 导航按产品组织：左边栏是你的产品，产品内一条主线：广告想法 → 测试 → 结论。
5. 现有的诚实规则一条不降：事实要有出处；没有出处的说法不进广告；没核对的不能导出去投；每个比较对象的订单不够就不下结论；示例数据不和真实证据混在一起；历史记录不改写；每次付费调用有预留和结算；租户隔离。

### 不做

- 不改判断算法和判断协议的默认值。
- 不做 Meta 自动取数（等 Meta 审核，见 §5.4），不做任何 Meta 写入。
- 不迁移旧数据，不删除高级工作台和旧页面的路由。
- 不重做本地化、放量、创意库。竞品只换位置，拆成独立页面，内容不重做。
- 不追求和设计稿像素一致。

### 不能变成的样子

- 为了少一次确认，系统替用户“确认”事实，或把用户没见过的预算和目标写进历史记录。
- 在现有流程旁边再加一个并行入口，变成第四代并存。
- 主流程出现内部编号或内部术语。
- 用示例图冒充用户自己产品的广告。
- 事实没核对的图被导出去投放。

## 3. 约束

- CLAUDE.md 的不变量全部适用：控制面与领域服务的职责划分、TenantContext、PostgreSQL RLS、不可变版本与只追加证据、付费调用走持久任务加幂等加预留、Meta 写入保持关闭。
- 小轮冻结时，快照里的方案仍是今天完整的 `TestPlan` 形状，另带产品理解。评估、导出、看板和旧小轮都读这个形状，不能破坏。
- 已有项目（`input` 到 `plan_confirmed` 这套状态）继续可读可用。
- 界面有英文和简体中文两套文案，新页面两套都要有。
- 客户工作区的 Meta 真实读取目前被 ADR 0009 限制在平台工作区，自助接入还要等 Meta 的商家认证和 `ads_read` 高级权限（见 `docs/research/2026-09-01-meta-customer-access-path.md`）。
- 仓库公开：文档、测试、示例只用虚构品牌。

## 4. 考虑过的做法

| 做法 | 是什么 | 取舍 |
| --- | --- | --- |
| A. 只换界面 | 后端不动，重画页面，预填并合并确认 | 改动最小；但出图前仍要确认整份方案，根因还在 |
| **B. 把方案拆成两段** | 广告内容和测试设置分开确认；读完产品就能出草稿，核对挪到导出前 | 能做到“先看图”；要改后端规则和数据结构，工作量明显大于 A |
| C. 另加快速入口 | 现有流程不动，旁边新做“贴链接出草稿” | 最快见效；但看完图掉回现在的复杂页面，并且多一代并存 |

**选定 B**（产品负责人，2026-11-16）。不选 A 是因为它不解决根因；不选 C 是因为这个产品已经叠了三层，每次都是新增一层、旧的留着。

## 5. 新流程

主线是五个画面（§5.1–§5.5），属于同一个产品。它们是可以来回切换的视图，不是只能往前走的向导。主线之外的画面见 §5.6，现有功能各自去了哪里见 §5.7，全部 15 个画面怎么分步见 §10。

### 5.1 开始

```
贴一个产品链接，先看看广告长什么样
[ https://acmecharge.example/products/home            ]
[ 也可以把产品图片或页面截图拖到这里 ]
广告投到 [ 美国 · 英语广告 ▾ ]
你的 API Key [ 粘贴 OpenAI 或 Gemini 的 Key ]  怎么拿到？   ← 只在工作区还没有 Key 时出现
[ 开始 · 最多 $0.80 ]
示例：Acme Charge 的 3 个主张、6 张广告（静态图，标“示例”）
```

示意里的金额是举例，实际数字由系统按首批的调用算出。

- 入口是 `/w/{slug}`。工作区没有产品时显示这个画面；有产品时进入总览（§5.6）。
- 输入沿用现有产品录入的粘贴框：链接、文字、图片任意组合，抓取的安全限制不变。
- “广告投到”决定投放市场和广告语言，带默认值。用户在这里的选择就是对广告语言的确认，后面不再单独确认。
- 点“开始”之后，系统自己把后面三件事接着做完：读产品、想主张、出图。关掉页面也继续，回来能看到进度。
- 首批规模固定：3 个主张，每个 2 种讲法，每种 1 张，共 6 张。产品资料支撑不了 3 个主张时可以更少，至少 2 个。
- 开始按钮上写首批的最高费用，点击即确认，这是首批唯一的费用确认。
- Key 的三种情况：
  - 工作区已有可用的 Key：不出现 Key 这一行。
  - 没有 Key，当前用户是 Owner：表单里多一行 Key，按钮变成“保存 Key 并开始 · 最多 $X”。Key 仍存进现有的凭据机制，加密、版本和审计不变，只是多了一个入口；设置页的入口保留。
  - 没有 Key，当前用户不是 Owner：不显示 Key 输入，提示“请工作区 Owner 先添加 API Key”，开始按钮不可用。只有 Owner 能添加 Key，这一点不变。
- Key 不能用要尽早说清楚。现在保存 Key 不会向供应商验证。新流程要求用户在出图开始之前得到明确的提示和原因，不能等到中途才失败。
- 开始页下方放一组 Acme Charge 的静态示例图，明确标“示例”，让还没有 Key 的用户先看到会得到什么。不做可点的示例产品。

### 5.2 读产品

```
正在读 Acme Charge Home
读到的产品                         进度
✓ App 预约充电   （出处：…）        ✓ 读取产品页
✓ 负载均衡       （出处：…）        ✓ 整理产品事实
✓ IP55 外壳      （出处：…）        ● 想购买主张
! “比家用插座快 3 倍”没有出处，     ○ 出图
  不会用在广告里
```

- 产品只读一次。用户只看到一份结果：产品名、事实（每条带原文出处）、没有出处的说法（列出来，但不用）、AI 的猜测（受众、使用场景、顾虑）、候选产品照片、从页面看到的品牌颜色。
- 事实一条条出现，不等全部完成。目标是 30 秒内出现第一批事实。
- 现有的机器检查继续在想主张之前执行，不依赖用户：事实的引文必须能在原始资料里找到；认证、参数、价格类的说法必须有原文依据。
- 资料是图片或截图时，从图里读出的文字存为原始资料，出处写“来自你上传的图片”，同样受上面两条检查约束。
- 这时所有事实都是“未核对”，不拦后面的步骤。
- 会打断的只有三种情况：链接里有多个型号，需要用户选一个；抓取失败，提示改贴介绍或截图；资料撑不起 2 个主张，这时在出图之前停下，说明缺什么，请用户补充资料，不产生出图费用。
- 没有可用的产品照片（只贴了文字，或页面图片都不合格）时照常出图，广告上标“没有用产品照片”，并在主张页提示“加一张产品照片，图里的产品会更像”。
- 某一步失败时，页面说明是哪一步、为什么，并给“重试”。已经完成的部分保留。
- 出错的不是某一步，而是我们自己在步骤之间出了错（代码或数据库的错，自动重试过还是不行）时，页面说清楚是我们这边的问题，不说“可能是暂时的”；仍然可以在原处再试，但再试不提高用户确认的最高费用（#269）。

### 5.3 广告想法

```
3 个主张，6 张广告草稿
主张 1 晚上插上，不用再管      主张 2 放在室外也放心      主张 3 不怕家里跳闸
[图][图]                      [图][图]                  [图][图]
讲法：睡前插上的一刻           …                         …
[留下这张] 修改                                                    AI 读到的产品
                                                                   事实 3 条（未核对）
已留下 4 张     [只下载图片]  [拿去测试]                            参考照片（未核对）
                                                                   没用上的说法 1 条
```

- 每个主张一组：一句主张、为什么值得试（可展开）、它的广告。每张广告下面一句话说明讲法。
- 每张广告可以“留下”或取消，可以“修改”（改文案或提修改意见后重出这一张）。还可以“再来一个主张”“换一种讲法”“加一个我自己的主张”。这些追加生成的按钮上直接写最高费用，点击即确认。
- 右侧一栏“AI 读到的产品”：事实（逐条核对、改、删）、参考照片、没用上的说法、品牌。
- **草稿和可导出。** 一张广告满足下面三条才“可导出”，否则带“草稿”标记：
  1. 它的主张和讲法引用的事实都已由用户核对，并且和出图时一致；
  2. 它用到的产品参考照片已由用户核对为真实产品照片且有权使用；没有用产品照片的广告，要用户在下载前核对时明确确认图里的产品外观没有问题；
  3. 检查没有未处理的问题，并且检查对照的是当前已核对的事实。
- 核对时如果改了或删了一条被引用的事实，或者否定了一张参考照片，用到它的广告标为“需要重出”，不能导出。
- 出图后系统自动做检查。只有需要注意的结果才显示在图上，例如“图里的字和文案不一致”。通过的不显示。
- “只下载图片”和“拿去测试”都会先经过一次“下载前核对”：只列出留下的广告需要的事实、照片和待处理的检查结果，一次确认。
- 一张都没留下时，两个按钮不可用。
- 广告想法页不放竞品入口。做过竞品扫描时，主张卡片上用一行字标出和竞品重合或还没人说；没扫描过就不显示。**第 1 步不含这一行**（维护者 2026-11-17 决定，#204）：要让它出现，起草主张时得读竞品扫描结果，这是策划那一步的改动，放到第 1 步之后再排。
- “上传我自己的图”沿用现有的外部素材打标：传上来的图归到某个主张和讲法下，和系统出的图一样可以留下、测试。也可以从素材库里选已有的图。
- 右栏还有“出图设置”（用哪家出、画幅、清晰度、每种讲法出几张）和可选的引导问题。
- “修改这张广告”里可以改文案、提修改意见后重出，也可以直接处理图片：裁剪旋转、放大、去背景、擦掉一块。每次得到一个新版本，旧版本保留、可对比、可换回，新版本要重新检查。

### 5.4 拿去测试（第 2 步交付）

```
测试这 4 张广告                                  够下结论
到这一步才需要回答三个问题                        每个主张预计 20 单
这一轮想弄清：两个主张里哪个值得继续花钱           够下结论需要 $1,200
一单花多少钱以内算成功   [ $30 ]                  预计 12 月 2 日出结论
这一轮花多少   ( $300 ) ( $600 ) (•$1,200)        1 下载广告包
投多久         (•7 天) ( 14 天)                   2 在 Meta 建广告
▸ 其他都按默认                                   3 把报表传回来
                                                 [ 下载广告包，开始测试 ]
```

- 这一轮比什么，由系统根据留下的广告决定，并用一句话告诉用户：留下的广告跨两个以上主张，就比主张；只有一个主张、两种以上讲法，就比讲法；只有一张，就只看它是否达标。这对应现有“筛选角度 → 匹配表达 → 确认组合”的路线，不改路线。
- 只问三件事：一单多少钱以内算成功；这一轮花多少；投多久。
- 右侧实时告诉用户够不够：每个比较对象需要的订单数取判断协议的 `min_purchases`（默认 20），“够下结论需要的钱 ≈ 比较对象数 × 20 × 目标成本”。预计订单数按“成本刚好达到目标”估算，并这样写明。三档：够下结论（每个对象预计不少于 20 单）、能看出方向（不少于 10 单）、只能看个大概。钱不够时给一个建议：少比几个。
- 预计出结论的日期要写出来。现有协议默认投放结束后再等 8 天让订单归因完成，按系统的成熟规则（今天晚于结束日加 8 天），7 天的测试从开始那天算是第 16 天出结论（原文写第 15 天，少算了一天；#245 更正）。
- “其他都按默认”折叠：受众（AI 读到的受众）、落地页（贴的产品链接）、优惠（无）、版位、怎么算一单（7 天点击加 1 天浏览）、广告账户时区（浏览器时区）、开始日期（明天）、预算分配（各对象平均）、判断门槛（协议默认）、整个测试的上限（默认最多 3 轮，总预算为首轮的 3 倍）。每项可改。
- 测试设置里的文字项（这一轮的问题、改变了什么、保持什么、局限、停止规则）由代码按模板生成，不为此再做一次付费的 AI 调用。
- 点“下载广告包，开始测试”等于同时做完今天分开的四件事：确认方案、冻结小轮、记录质量审核、生成导出包。这四件事在后台仍各自记录、各自可审计。
- 因为方案是按留下的广告生成的，现有“导出必须覆盖方案里每个组合”的规则自然满足。
- 数据回来的方式第一版不变：用户在 Meta 建广告，把报表传回来。简化一处：报表里有广告名时，用广告名里的稳定短键预填“哪条广告对应哪张图”，用户确认一次；正式对应仍按 Ad ID 记录。
- Meta 只读自动取数是之后的升级，等 Meta 审核通过并另行决策（涉及 ADR 0009）。
- 测试开始后是“测试进行中”画面：三步清单、传报表、广告对应、目前看到的数字（标明还不是结论）、这一轮的安排。可以更正之前传的报表，记录实际投放和计划的偏差，提前结束这一轮。
- “测试记录”列出这个产品的每次测试和每一轮、数据更正记录，以及改版前建的测试。

### 5.5 结论（第 3 步交付）

```
“晚上插上，不用再管”值得继续投
主张 1  达标      $20/单（目标 $30 以内） 34 单  大概在 $15–$29 之间
主张 2  还看不出来 $34/单（暂时）         9 单   还差约 11 单
建议的下一步：给主张 1 再做 2 种新讲法   [ 开始下一轮 ]  先到这里
目前对这个产品的认识：已有数据支持的 / 还不知道的
▸ 每日数据和判断规则
```

- 最上面一句话结论。每个比较对象一张卡，三种状态：达标、没达标、还看不出来。
- 所有数字来自现有评估结果，页面不另外计算。区间用“大概在 X–Y 之间”表达。
- 写明结论的范围：这是这几张图的结果，不代表这个主张怎么拍都行。
- “还看不出来”要说明还差多少单。
- 建议的下一步有一个主建议，对应现有路线的下一阶段；另有“只换人物、背景或标题再测”（现有的元素优化）和“先到这里”。
- 每日数据、判断规则、算法版本收在折叠里。“让 AI 解释这个结果”沿用现有的解读能力，按钮上写最高费用。
- 达标之后，结论页出现“做成其他市场的版本”（本地化）和“放量”两个入口。规则沿用现有的证据交接：达标的确切广告可以准备本地化；放量要等用新图再测一轮也达标之后才出现，在那之前写明原因。

## 7. 方案拆成两段

| 段 | 包含的现有字段 | 什么时候定 |
| --- | --- | --- |
| 广告内容 | 广告语言、策略语言、市场、主张（含理由和引用的事实）、讲法、创意组合（标题、正文、画面说明、英文出图说明、检查点）、风格说明、品牌底线引用、竞品快照引用 | 读完产品后由 AI 起草，可以一直追加 |
| 测试设置 | 阶段、这一轮的问题、比较方式、改变和保持的条件、局限、结论范围、受众、版位、优惠、落地页、基准、币种、总预算、本轮预算、周期、分配方式、判断规则、测试组 | “拿去测试”时，根据留下的广告和用户的三个回答生成 |

- 广告内容是一个会增长的池子，每次变化仍留版本。一次测试从池子里取“留下”的那部分，冻结成快照。
- 新增两个概念：广告的“留下”标记；广告的“草稿 / 可导出 / 需要重出”状态（由 §5.3 的三条推出来，不是手填的）。
- 冻结小轮时把两段合成今天的完整方案形状写进快照。

## 8. 费用和 Key

**决定：仍然先配 Key**（产品负责人，2026-11-16）。客户用自己的 Key 付 AI 费用，平台不代付，ADR 0005 和权益合同不变。

考虑过“平台垫付首批草稿”：每个工作区一次性的首批额度，新用户一次确认都没有。没有采用，因为要改现有约定，并且由平台出钱。

在这个决定下，开头要做到：

- **配 Key 留在开始页里完成**（§5.1），不用先去设置页。
- **一个 Key 就够。** 工作区只有一家受支持的 Key（OpenAI 或 Gemini）时，也要能跑完读产品、想主张、出图、检查。现状是产品录入只认 OpenAI，策划认部署配置的那一家，需要补齐。第 1 步至少保证其中一家用一个 Key 跑完全程，并在开始页写明是哪一家；两家都支持是目标，由实现者核实工作量后定。
- **首批只确认一次费用。** 读产品、想主张、出图、检查的最高费用，再加一次想主张的费用，合成一个数字，写在开始按钮上。多出的这一次只在应用拒收主张草稿时用来重新起草一次（维护者决定，#193）；没用上不收费。后台仍然逐次预留、逐次结算。中途如果会超过这个数字，停下来问用户。
- **不静默改用示例。**
- **首批之后的每次付费动作，最高费用写在按钮上。**
- 新工作区已有默认的花费上限（单次 5 美元、24 小时 20 美元、每期 100 美元），用户不需要先去设置。

| 业务达标 | 达标 |
| 大轮、小轮 | 测试、第 N 轮 |
| 冻结小轮 | 不出现 |
| 交接包、导出包 | 广告包 |
| 绑定 | 对上 Meta 里的广告 |
| QC、Deterministic check | 检查（有问题时才出现） |
| Spend Guardrail、预留 | 最多花 $X |
| BYOK、凭据 | 你的 API Key |

英文文案在第 1 步实施时按同样的原则起草。代码里的 generation draft 是出图前的配置对象，和界面上的“草稿”不是一回事。

## 10. 分三步交付

设计稿共 23 屏：电脑上 17 屏，手机上 6 屏。归到三步里：

| 步 | 画面 |
| --- | --- |
| 第 1 步 | 左边栏和产品内四个视图的框架、开始、读产品、广告想法、下载前核对、修改这张广告、产品资料、总览、设置里的 Key；“出错和待处理”里和 Key、读产品、出图、花费上限有关的几种 |
| 第 2 步 | 拿去测试、测试进行中、测试记录；“出错和待处理”里和报表有关的几种 |
| 第 3 步 | 结论和它的对比表，含本地化、放量、AI 解释的入口 |
| 不在这三步里 | 竞品汇总页和素材库的重画，含连续看图（第 1 步把竞品从营销测试页里拆成独立页面、把素材页接到新入口上，内容都不重画）；本地化、放量、创意库的重做。手机上的排法不是单独一步，每一步做到的画面都要在手机宽度可用 |

### 第 1 步：框架、开始、读产品、广告想法、产品资料

范围：§5.1–§5.3、§5.6 的导航和总览、产品资料、把竞品拆成独立页面、§6 里和出图有关的关卡、§7 的拆分、§8。

过渡期不搭桥：第 1 步的主张页只有“下载图片”，“拿去测试”等第 2 步一起出现。原因是现有的素材复用只在已冻结的小轮里可用，要把留下的图带进旧页面，得先在旧页面重读一遍产品、确认一份和这些图无关的新方案，体验比不带更差；专门为旧页面搭桥又是第 2 步会丢掉的工作。

第 2、3 步上线之前：“测试”列出这个产品已有的测试，并提供“新建测试（现在的流程）”，从头走现在的页面，留下的图不会带过去；“结论”链接到现有测试页里的结果。其他旧的新建入口改为跳到新的开始页。第 1 步是单独对用户开放，还是等第 2 步一起开放，发布时再定，不影响要做的东西。

验收：

1. 空工作区贴 `https://acmecharge.example/products/home`，点一次“开始”，之后没有任何必须的点击，页面依次出现事实、主张、广告草稿。唯一的费用确认是开始按钮上的最高费用。
2. 主流程不出现内部编号，也不出现 §9 左列的词。
3. 事实未核对时广告带“草稿”标记，下载停在“下载前核对”；核对后可以下载，下载的只有留下的图。
4. 核对时改掉一条被引用的事实，用到它的广告变成“需要重出”，不能下载。
5. 没有出处的说法不出现在任何主张、文案里。
6. 刷新页面、重启 Web、API、Worker 后进度恢复，不重复出图，不重复计费；结果不确定的调用沿用现有的核对机制。
7. 另一个工作区的成员和非成员看不到也操作不了这些产品、主张和图。现有只有 Owner 和 Member 两种角色，都能导出，本设计不新增角色限制。
8. 没有 Key 时不出图，也不出现冒充的示例图；开始页的示例图标明“示例”。没有 Key 的 Owner 在开始页贴入 Key 后直接开始，不用去设置页；不是 Owner 的成员看到明确提示。Key 不能用时，用户在出图开始之前得到明确提示。工作区只有一家供应商的 Key 时，全程能跑完。
9. 手机宽度可用，英文和简体中文都完整。
10. 已有测试照常打开；高级工作台的路由和黄金路径 e2e 仍通过。
11. 竞品从左边栏进入，是独立页面；选产品后，现在竞品区能做的事都能做。广告想法页没有竞品入口。
12. 总览里每个产品显示当前状态和一个主要按钮。
13. 产品资料里能核对、修改、删除事实，补充出处，管理照片和品牌。

### 第 2 步：拿去测试

范围：§5.4。验收：

1. 从留下的广告到下载广告包，用户最多回答三个问题，加一次下载前核对。
2. 钱不够下结论时，下载前页面已经写明“只能看个大概”和够下结论需要多少。
3. 冻结的小轮快照和现有形状兼容；导出、回传、评估的现有验收场景仍通过。
4. 上传的报表能按广告名里的短键预填对应关系，用户确认后才生效。

### 第 3 步：结论

范围：§5.5。验收：

1. 第一屏有一句话结论，每个比较对象一张卡，状态只有达标、没达标、还看不出来三种。
2. “还看不出来”写明还差多少单。
3. 页面上的数字都能在评估结果里找到同一个值。

## 12. 留给实现者决定

- 方案是一份文件两个确认状态，还是两份文件。只要 §3 的快照约束和旧项目兼容成立。
- “开始”之后的三件事怎么串起来。要求是关掉页面也继续、可恢复、不重复计费。
- 出图今天要求一个已确认的产品锚点，新流程里出图在确认之前。需要让未确认的产品草稿也能作为出图来源，并保证导出时它已经是确认过的版本。
- 一张广告“引用了哪些事实”的精确判定，以及事实变化后哪些检查要重做。
- 自动检查的触发时机，是否并入首批总价。
- 测试设置里文字项的模板。
- 页面怎么拆，现有看板、检查、改图组件复用多少。
- 首批的默认画幅和模型。
- Key 的校验方式，首批最高费用怎么算。
- 开始页示例图的来源（建议用虚构的 Acme Charge 测试页实际跑一遍得到）。
- 总览里“现在最该做的事”怎么排。建议的顺序：有出错待处理的，测试中缺报表的，有结论还没看的，留下了广告还没测试的，有草稿还没处理的。
- 竞品拆成独立页面后，原来“产品理解起草之后才能打开”的条件怎么处理。

## 13. 还没定的事

1. **“给这个主张补预算继续投”。** 现有规则要求判断协议在投放前冻结、只在最终时点判断，不能反复看数据直到结果有利。补预算需要先定规则（例如冻结时就写明最多可延长多少），所以第 3 步的第一版不提供这个动作，只写明还差多少单。
2. **Meta 自动取数。** 取决于 Meta 的审核进度。
3. **“大约几分钟”的具体数字。** 做出来量过再写进文案。

## 14. 本文里由作者做的决定

下面这些不是产品负责人说过的，是作者的提议，请过目：

- 首批固定 3 个主张、6 张图。
- 用户不确认主张就直接出图。
- 未核对的产品照片可以用来出草稿。
- 方案检查项由系统自动处理，AI 的引导问题首批不问。
- 测试设置的文字项用模板生成，不再调用 AI。
- 测试页只问三个问题，其余给默认值；整个测试默认最多 3 轮、总预算为首轮的 3 倍。
- 第一版保留上传报表，只加“按广告名预填对应”。
- 高级工作台收在左边栏的“更多功能”里，默认折叠，和现在一样；本地化和放量另外在结论页达标后出现（§5.7）。
- 左边栏保留，内容换成产品列表；已有产品时落地页是总览（§5.6）。
- 旧测试不迁移，在原页面继续，标“旧版”。
- 开始页给还没有 Key 的用户看一组标明“示例”的静态图，不做可点的示例产品。
- Key 在开始页里配；Key 不能用要在出图开始之前告诉用户。
- 第 1 步至少保证一家供应商用一个 Key 跑完全程。
- 首批的几次调用合成一个最高费用，写在开始按钮上。
- 第 3 步第一版不提供“补预算继续投”。
- 竞品独立后放在左边栏，进去先选产品；和广告想法只留两处连接（§5.6）。对比表放在结论页（§5.7）。
- 23 个画面怎么归到三步（§10）。
- 手机上的排法（§5.8）。
- 第 1 步不提供“拿去测试”，不为旧页面搭桥（§10）。
- 只有用户核对过的事实和照片算已确认，其余保持为 AI 的提议（§6）。
- 从图片或截图里读出的文字可以作为出处，标明来自用户上传的图片（§5.2）。
- 没有产品照片时照常出图，下载前要用户明确确认外观（§5.2、§5.3）。
- 资料撑不起 2 个主张时在出图前停下（§5.2）。
