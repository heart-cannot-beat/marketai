# Control-plane fork hardening manifest

This file records what the MarketAI fork changed relative to the pinned upstream
commit recorded in [`UPSTREAM.json`](UPSTREAM.json). It is the human-readable
half of the import; the machine-readable half is `UPSTREAM.json`, and the
enforcement half is `__tests__/fork/disabled-capabilities.spec.ts`.

Upstream: BoxyHQ SaaS Starter Kit, `abc9b686823cbfb4973c79bc36fea37a3244be6c`
(v1.6.0, 2026-05-08), Apache-2.0.

## Import mode

Curated subset, not a full mirror. 327 upstream tracked files were reviewed; the
files backing removed capabilities were dropped rather than feature-flagged, so
a disabled capability has no route, no navigation item, no background handler
and no dependency. Upstream repository-management files (`.github/`,
`.do/`, `app.json`, `Procfile`, `.release-it.json`, `CODE_OF_CONDUCT.md`,
`CONTRIBUTING.md`, `docker-compose.yml`) were not imported: CI and deployment
are owned by this repository, and an inherited Dependabot config would update
the fork without review.

## Database ownership

Prisma is configured with the control-plane datasource only, and the schema
contains identity, Workspace, membership, invitation and password-reset records
only. MarketAI domain tables are owned exclusively by SQLAlchemy
(FastAPI/Worker) in a separate database with a separate role. Role separation is
provisioned by `deploy/postgres/control-plane-domain-roles.sql` and proved by
`__tests__/integration/database-role-isolation.spec.ts` and
`tests/test_database_role_isolation.py`.

## Session revocation

The browser holds a JWT cookie, but the JWT is not the authorization decision.

- Sign-in creates a `Session` row and puts its id in the token's `sid` claim.
- The NextAuth `session` callback re-reads that row on every session read and
  returns nothing when it is missing or expired.
- The middleware asks `/api/auth/session` — which runs in the Node runtime and
  therefore performs that lookup — instead of trusting `getToken()` alone, so a
  revoked token cannot even reach a page.
- Sign-out, password change, password reset and removing an entry in Manage
  Sessions all delete rows, and take effect on the next request. Every
  sign-out path routes through the same fail-closed handler, including
  NextAuth's own `/api/auth/signout`.
- Minting a session re-checks `User.credentialVersion` under a row lock, so a
  sign-in that verified credentials a reset or an email change has since
  withdrawn fails instead of producing a session with stale authority.
- Changing the account's email address is a credential change for the same
  reason: reset links are bound to the account, so one already delivered to the
  previous address would otherwise still take it over.
- If the sign-out delete fails for any reason other than "already gone", the
  request returns 503 and the cookie is left alone. Clearing it while the row
  survived would report success to the person signing out while every copy of
  the token kept working.

The session cookie carries no authorization epoch and does not need one: the
session row is re-read on every request, and role, membership and identity are
read from the database at each check rather than cached in the token, so
revoking the row is enough to stop everything it authorized.

That reasoning does **not** carry over to the delegated ES256 domain token in
the identity-seam ticket. Once FastAPI has been handed such a token it validates
it independently, so deleting a control-plane session row cannot invalidate a
token that is already issued and not yet expired. That token must carry an
authorization epoch of its own.

## Interface language

Upstream shipped English only. This fork serves `en` and `zh-CN` (#252):

- `User.locale` is a nullable column restricted by a `CHECK` to the offered
  languages (`prisma/migrations/20261026090000_user_locale`). Null means
  "follow the browser". It is written only through `PUT /api/users`, which
  takes no user id and updates the session's own account; anything else in
  the body is dropped (`__tests__/api/user-locale.spec.ts`,
  `__tests__/integration/user-locale.spec.ts`).
- The session callback re-reads it from the `User` row like the other
  identity fields, and the middleware moves page requests to it, else to the
  `NEXT_LOCALE` cookie, else to `Accept-Language`. Redirects are built on
  `APP_URL`, like the sign-in redirect, and API calls, `/_next/data`
  requests and non-GET requests are never redirected.
- The domain proxy sends FastAPI the same resolved language as
  `X-UI-Language` (#255), built server-side; a browser-sent header of that
  name is dropped like every other one. FastAPI uses it for wording only,
  never for the Workspace, actor or role, which still come from the token
  (`__tests__/api/domain/v1/w/domain-proxy-handler.spec.ts`).
